# 구글시트로 할까, Firebase로 할까

결론부터: **Firebase(Firestore)를 원본 저장소로 쓰고, 구글시트는 "입력 창구 + 백업"으로 쓰는 것**을 권합니다.
이 저장소의 앱은 그렇게 만들어져 있습니다.

## 왜 구글시트만으로는 부족한가

선생님이 원하시는 흐름은 **입력 → 확인 대기 → 승인**, 그리고 **관리자만 오기재를 수정**하는 것입니다.
구글시트는 여기서 세 가지가 막힙니다.

| 필요한 것 | 구글시트 | Firestore |
|---|---|---|
| 줄(행) 단위 권한 | 없음. 편집 권한을 주면 **남의 줄도 지울 수 있음** | 규칙으로 "본인 글만 수정, 승인은 관리자만" 강제 |
| 실시간 반영 | 앱이 주기적으로 물어봐야 함. 사용자당 분당 60회 읽기 제한 | 바뀐 즉시 모든 기기로 밀어줌 |
| 동시 입력 | 같은 칸을 동시에 고치면 마지막 사람이 덮어씀 | 문서 단위로 안전하게 병합 |
| 승인 이력 | 수정 기록이 시트 히스토리에 섞임 | 이력 컬렉션에 누가·언제·무엇을 남김 |
| 오프라인 | 사실상 불가 | 캐시로 열람 가능, 온라인 되면 자동 동기화 |

즉 **"보여주기"는 시트로 되지만 "결재 흐름"은 시트로 안 됩니다.**

## 그래서 이렇게 씁니다

```
각 계 담당자
  ├─ 앱에서 직접 입력 ─────────────┐
  ├─ 한글(.hwpx)·엑셀 파일 올리기 ─┤
  ├─ 메신저 글 그대로 붙여넣기 ────┤→ 미리보기 표에서 확인 → 제출
  └─ 구글시트에 자유롭게 적기 ─────┘        (상태: 확인 대기)
                                               │
                                        관리자(선생님)
                                     승인 / 반려 / 오기재 수정
                                               │
                                          Firestore
                                    (모든 기기 실시간 동기화)
                                               │
                     ┌─────────────────────────┼──────────────────────┐
              일일·주간·월간 화면      나이스 결재 문구·메신저 안내      한글(.hwpx) 파일
```

구글시트는 이 그림에서 **왼쪽(입력 창구)** 자리입니다.
`sheets/Code.gs` 를 시트에 붙여넣으면, 담당자가 아무 형식으로나 적은 글을 표로 정리해 주고,
앱의 [불러오기] 탭이 그 시트를 주소 한 줄로 받아옵니다.

## 비용

교직원 50명, 하루 200건 수정 기준이면 Firebase **무료 요금제(Spark) 안**에서 끝납니다.
(무료 한도: 하루 읽기 5만 / 쓰기 2만 / 저장 1GiB)
한 학교 규모에서 이 한도를 넘기기는 어렵습니다. 카드 등록도 필요 없습니다.

## 구글시트만으로 가야 하는 경우

- 교육청 정책상 외부 서비스 계정을 못 만든다
- 이미 학교 구글 계정(Workspace for Education)에 모든 자료가 있고 그 밖으로 나가면 안 된다

이때는 `app/js/config.js` 의 `backend` 를 `'local'` 로 두고,
**앱은 열람·문서 생성 도구로만**, 원본은 시트로 관리하는 방식이 현실적입니다.
승인 흐름은 시트의 "상태" 열 + 조건부 서식으로 흉내 내되, 권한 강제는 포기해야 합니다.

## 정리

| | 추천 |
|---|---|
| 지금 바로 혼자 써 보기 | `local` (설정 불필요, 이 컴퓨터에만 저장) |
| 학교 전체가 같이 쓰기 | **`firestore`** ← 권장 |
| 담당자 입력 창구 | 앱 직접 입력 + 파일 업로드 + **구글시트** 병행 |
| 백업 | 설정 탭의 [전체 내려받기(JSON)] 를 학기마다 |
